# ESP32 HUD — спецификация канала, v1 (черновик)

Канал «Android → ESP32-HUD» проектируется **с нуля**. Формат WiiYii C1
(`src/YandexHudHeadUnit/HudProtocol.cs`) не используется и не наследуется.

Статус: **проект, не реализован**. На стороне Android транспорт — `IHudTransport` /
`IHudLocationTransport` (`src/YandexHudHeadUnit/HudTransport.cs`), кодировщик v1 ещё не написан.
Источник данных — `YandexNotificationBridge.BridgeState` (то, что реально читается из Навигатора).

Первый этап — **групповая абстракция**: передаётся не «кадр экрана», а набор независимых
групп данных. Каждая группа живёт своей жизнью; отсутствие группы гасит только её зону.
Формат групп расширяем (TLV), чтобы добавление данных не ломало прошивку.

MUST / MUST NOT / SHOULD / MAY — нормативные (RFC 2119).

---

## 1. Инварианты

1. `type=1` — **полный снимок состояния**: все группы, которые сейчас есть, в одном
   сообщении. Частичных обновлений состояния нет.
2. **Отсутствие группы = «нет данных» = очистка её зоны.** Отдельных команд «clear» нет.
3. `type=2` (позиция) — **независимый поток** со своей частотой; он не влияет на остальные
   группы и не обязан приходить в каждом снимке.
4. **Камера и манёвр — разные группы.** Камера никогда не отменяет и не подменяет манёвр.
5. Свежесть данных — забота **отправителя**: он сам перестаёт слать устаревшую группу
   (и может переотправлять актуальную группу «взаймы»). Приёмник не экстраполирует.
6. Незнакомые `version`, `type`, TLV-id, значения enum и резервные байты **игнорируются**;
   остальные группы применяются.
7. Все многобайтовые целые — **little-endian**, `f32`/`f64` — IEEE-754 LE, `NaN` = нет значения.
8. Приёмник не хранит историю: снимок самодостаточен, повторы и перестановки безопасны.

## 2. Группы данных

| id | Группа | Состав | «Нет данных» | Источник |
| --- | --- | --- | --- | --- |
| `0x01` | G0 Сессия | `mode` | только `idle` | `BridgeState.Active`, `Mode` |
| `0x02` | G1 Манёвр | `kind`, `distance_m` | обе группы нет | `Maneuver`, `NextTurnDistanceMeters` |
| `0x03` | G2 Полосы | `count`, `lanes[]` | группы нет | `Lanes`, `LanesObservedAtUnixMilliseconds` |
| `0x04` | G3 Следующая улица | UTF-8 | группы нет | `Road` |
| `0x05` | G4 Текущая улица | UTF-8 | группы нет | `CurrentRoad` |
| `0x06` | G5 Лимит | `kph` | группы нет | `SpeedLimitKph` |
| `0x07` | G6 Камера | `distance_m` | группы нет | `CameraDistanceMeters`, `CameraObservedAtUnixMilliseconds` |
| `0x08` | G7 Дорожное событие | `kind`, `distance_m` | группы нет | `RoadEvent`, `RoadEventDistanceMeters` |
| `0x09` | G8 Остаток маршрута | `distance_m`, `time_s` | группы нет | `RemainingDistanceMeters`, `RemainingTimeSeconds` |
| `0x0A` | G9 Позиция | `lat`, `lon`, `speed`, `bearing`, `accuracy`, `timestamp` | группы нет | `HudLocation` |
| `0x0B` | G10 Мета | `source`, `flags`, `observed_at_ms` | группы нет | `BridgeState`, `YandexScreenService.Connected` |

### 2.1 Правила групп

1. `distance_m` принадлежит своей группе (манёвр/камера/событие) и отдельно не передаётся.
2. `mode` — единственная группа, которая обязательна в `type=1`.
3. `mode=free` (обзор дороги без маршрута): G1/G3/G8 отсутствуют по определению, живут
   G4, G5, G6, G7, G9.
4. `rerouting` и `finish` — **состояния G1**, не отдельные группы. При `rerouting` G2 и G6
   не отправляются (предупреждения неактуальны), G8 продолжает жить.
5. Панель камеры в Навигаторе вытесняет balloon манёвра. В протоколе это **только G6**:
   G1 в этом цикле отсутствует, G3/G4/G5/G8 продолжают передаваться. Показ старой стрелки
   на 2–4 с — политика отправителя (§9.2), а не свойство камеры.
6. «Камера» **не является** значением `road_event`: камеры живут только в G6. Сейчас код
   кладёт их и в событие (`ScreenNavigationReader.cs:105`) — при кодировании значение
   `Камера` в G7 не попадает.
7. Неизвестное значение enum внутри группы = вся группа отсутствует; остальные группы
   применяются как обычно.
8. G9 передаётся только при явно включённой пользователем передаче координат и только
   в `type=2`.

### 2.2 Решения этой редакции

| # | Решение | Причина |
| --- | --- | --- |
| D1 | «Держать» манёвр при кратком пропадании — отправитель, до 4 с | убирает мигание при панели камеры, прошивка остаётся простой |
| D2 | `left_wide`/`left_fork` и `right_wide`/`right_fork` **склеены** в одно значение | иконка не различает их (`ManeuverRecognizer.cs:61`), HUD-стрелка у C1 тоже одна (`HudProtocol.cs:53,57`) |
| D3 | При `rerouting` G2 и G6 не передаются | как в текущем коде (`BridgeState.cs:56-69`) |
| D4 | G9 — отдельное сообщение, по умолчанию выключено | своя частота (1 Гц), приватность |
| D5 | G3 и G4 — раздельные группы | экран сам выбирает, что показать в `route`/`free` |
| D6 | G10 — только диагностика, на экран не выводится | `source`/`screen_reader_connected` |

## 3. Транспорт

| Параметр | Значение |
| --- | --- |
| Роль | ESP32 = GATT peripheral, Android = central |
| Service UUID | `6b1d0001-9c4e-4b7f-a1e2-3f5d6c7b8a90` |
| Characteristic `nav` | `6b1d0002-9c4e-4b7f-a1e2-3f5d6c7b8a90`, `Write` + `Write Without Response` |
| Characteristic `status` | `6b1d0003-9c4e-4b7f-a1e2-3f5d6c7b8a90`, `Notify`, MAY (в v1 не обязательна) |
| Advertising | имя `YHUD-ESP32` и/или Service UUID |
| Pairing/bonding | не требуется |
| MTU | Android SHOULD запросить 247 (максимальное сообщение 197 B); прошивка MUST работать при MTU 23 и 247 |
| Запись | `Write Without Response` предпочтительно, иначе `Write` |
| Чтение/notify со стороны Android | не используются в v1 |

UUID — предлагаемые; при первом релизе зафиксировать. Смена UUID = несовместимая версия.

## 4. Контейнер сообщения

```
off  size field        value
0    1    version      1
1    1    type         1 = state snapshot, 2 = position
2    4    sequence     u32 LE, отдельный счётчик на каждый type
6    2    reserved     0 (игнорировать)
8    ..   tlvs         последовательность TLV (§5)
N-2  2    crc          CRC-16/CCITT-FALSE от bytes[0 .. N-3], LE
```

CRC: poly `0x1021`, init `0xFFFF`, refin/refout = false, xorout `0x0000`.
Тест: `crc16("123456789") == 0x29B1`. Несовпадение → отбросить сообщение, состояние
не менять. `len < 13` → отбросить.

## 5. TLV

```
off  size field
0    1    group   id из §2
1    1    len     длина value, 0..255
2    len  value
```

- Порядок групп произвольный; каждая группа MUST встречаться не более одного раза
  (при повторе приёмник MUST использовать последнюю).
- Незнакомый `group` → пропустить по `len`; остальные применить.
- `0x0C..0x7F` — резерв под расширения, `0x80..0xFF` — приватные, оба диапазона игнорировать.
- Неверный `len` для известной группы → отбросить **только эту группу**, не всё сообщение.

Раскладка `value` (смещения от начала value):

| Группа | len | Раскладка | Ограничения |
| --- | --- | --- | --- |
| `0x01` G0 | 1 | `mode u8` | 0 idle, 1 route, 2 free; иное → группа отсутствует |
| `0x02` G1 | 5 | `kind u8`, `distance_m u32` | kind 0 → группы нет; `distance_m` 0..2 000 000 |
| `0x03` G2 | 2..9 | `count u8`, `lanes u8[count]` | 1..8 позиций, иначе группы нет |
| `0x04` G3 | 1..64 | UTF-8 | §7 |
| `0x05` G4 | 1..64 | UTF-8 | §7 |
| `0x06` G5 | 1 | `kph u8` | 5..200; иное → группы нет |
| `0x07` G6 | 2 | `distance_m u16` | 1..5000; 0 → группы нет |
| `0x08` G7 | 3 | `kind u8`, `distance_m u16` | kind 1..5; `distance_m` 0 = не указано, 0..5000 |
| `0x09` G8 | 8 | `distance_m u32`, `time_s u32` | 0..50 000 000 / 0..3 000 000; оба 0 → группы нет |
| `0x0A` G9 | 36 | `lat f64`, `lon f64`, `speed f32`, `bearing f32`, `accuracy f32`, `timestamp i64` | только `type=2`; §5.1 |
| `0x0B` G10 | 10 | `source u8`, `flags u8`, `observed_at_ms i64` | source 0 notification / 1 screen |

### 5.1 G9 (position)

- Валидна, если `lat ∈ [-90,90]`, `lon ∈ [-180,180]`, `timestamp` не старше 5 000 мс
  и не в будущем, `accuracy` либо `NaN`, либо `0 < accuracy ≤ 100`.
- `speed`, `bearing`, `accuracy` могут быть `NaN` (неизвестны).
- `type=2` MUST содержать ровно одну группу `0x0A` и никаких других.
- `type=1` MUST NOT содержать `0x0A`.

## 6. Enum-значения

`maneuver.kind`:

| # | значение | смысл |
| --- | --- | --- |
| 0 | — | зарезервировано, означает «нет манёвра» |
| 1 | `left` | поверните налево |
| 2 | `right` | поверните направо |
| 3 | `left_wide` | плавно налево / держитесь левее |
| 4 | `right_wide` | плавно направо / держитесь правее |
| 5 | `left_sharp` | резко налево |
| 6 | `right_sharp` | резко направо |
| 7 | `u_turn_left` | разворот налево |
| 8 | `u_turn_right` | разворот направо |
| 9 | `straight` | двигайтесь прямо |
| 10 | `finish` | прибытие |
| 11 | `rerouting` | маршрут перестраивается |
| 12..255 | — | не присылаются; трактовать как «нет манёвра» |

`mode`: `0 idle`, `1 route`, `2 free`.
`road_event.kind`: `1 accident`, `2 roadworks`, `3 closed`, `4 hazard`, `5 speed_bump`.
`lanes[i]`: `bits 0..3` — направление, `bit 7` — рекомендуемая:

| # | lane direction |
| --- | --- |
| 0 | пусто (не использовать внутри `count`) |
| 1 | straight |
| 2 | left |
| 3 | right |
| 4 | slight_right |
| 5 | u_turn_left |

Порядок полос — слева направо, без разрывов. Других рисунков источник не даёт.

**Камера не входит ни в один enum**: только G6. Значение `Camera` из `NotificationReader.cs:57`
при кодировании превращается в отсутствие G1 + наличие G6.

## 7. Тексты

- UTF-8, 1..64 **байта** на поле, без управляющих символов и переводов строк.
- Транслитерация — только если шрифт HUD не поддерживает кириллицу; тогда это фиксируется
  вместе с `version`. Признак кодировки в сообщении не передаётся.
- Обрезка — по границе code point; приёмник MUST NOT рисовать битый глиф.
- Нет строки → нет группы (пустая строка не передаётся).

## 8. Фрагментация

Если сообщение не влезает в `MTU - 3`, оно режется на чанки:

```
off  size field
0    1    frag_magic  0xFA
1    1    frag_index  0-based
2    1    frag_total  1..255
3    ..   data        до (MTU-6) байт, последний чанк — остаток
```

- Первый байт записи `0x01` → целое сообщение, `0xFA` → фрагмент.
- Чанки одного сообщения идут подряд, 50 мс между записями.
- Сборка: `frag_total` совпадает, `frag_index` идут от 0 без пропусков; иначе сброс
  частичного буфера. Таймаут сборки — 1 с.
- CRC проверяется только на собранном сообщении.
- Максимальный снимок (197 B) при MTU 23 → 12 чанков; при MTU 247 — одна запись.

## 9. Время, свежесть, watchdog

### 9.1 Отправка

| Поток | Частота | Свежесть у источника |
| --- | --- | --- |
| `type=1` state | ~750 мс (цикл 50..1500 мс) | манёвр/маршрут/полосы 5 с, камера 10 с |
| `type=2` position | ≤ 1 Гц | 5 с, точность ≤ 100 м |

### 9.2 Политика удержания (отправитель)

- Группа перестаёт передаваться, как только данные устарели или исчезли; приёмник ничего
  не экстраполирует.
- **G1 (манёвр)** переотправляется до 4 с, если он ещё релевантен (`distance_m > 0`,
  маршрут активен), даже когда Навигатор показал панель камеры или кратко скрыл balloon.
  Это устраняет мигание стрелки без усложнения прошивки.
- Если манёвр относится к другому перекрёстку (изменилась улица/дистанция) — удержание
  прекращается, G1 не отправляется.
- Отдельного «hold_ms» в протоколе нет: прошивка не знает о политике отправителя.

### 9.3 Приёмник

| Событие | Действие |
| --- | --- |
| Нет валидного `type=1` 3 с | `STALE` — значок «нет данных», последний снимок сохраняется |
| Нет `type=1` 15 с | погасить все зоны G1..G8 |
| G9 старше 5 000 мс | скрыть позицию |
| Ошибка CRC | сохранить текущее состояние |
| Разрыв/повтор `sequence` | применить как обычно; счётчик только для диагностики |
| Отключение BLE | погасить навигацию за ≤ 1 с |

Приёмник MUST NOT сам продлевать или экстраполировать значения.

## 10. Отображение

Каждая группа владеет ровно одной зоной. Отсутствие группы гасит только её зону.

| Группа | Зона | Условие показа | Условие очистки |
| --- | --- | --- | --- |
| G0 `mode` | режим | всегда | — |
| G1 | стрелка + дистанция | `mode=route` и группа есть | группы нет / `mode≠route` |
| G2 | полосы | группа есть | группы нет |
| G3 | улица манёвра | `mode=route` и группа есть | группы нет |
| G4 | текущая улица | `mode=free` или в дополнение к G3 | группы нет |
| G5 | лимит (текст) | группа есть | группы нет |
| G6 | камера + дистанция | группа есть | группы нет |
| G7 | событие + дистанция | группа есть | группы нет |
| G8 | остаток (время/дистанция) | `mode=route` и группа есть | группы нет |
| G9 | позиция | группа валидна | устарела/нет |
| G10 | — | не отображается | — |

Правила:

1. `rerouting` (G1 kind=11) — отдельная индикация, без стрелки и дистанции.
2. `finish` (kind=10) — прибытие; следующий снимок — `mode=idle` и полный сброс.
3. Камера и манёвр показываются **одновременно**, если пришли обе группы.
4. `mode=idle` гасит G1..G8 одной посылкой, G6/G7 тоже (они живут только с маршрутом/обзором).
5. Форматирование: `< 1000` м → `N м`, иначе `N,N км`; `≥ 3600` с → `H ч MM мин`, иначе `M мин`.
6. Зоны MUST NOT перекрываться; обрезка текста — по code point.
7. Отрисовка — чистая функция снимка; анимация не должна менять состояние зон.

## 11. Пожелания к протоколу

### 11.1 Отправителю

1. Один цикл = один полный снимок; никаких «частичных» обновлений состояния.
2. Не отправляй производные строки («через 300 м», «1 ч 20 мин») — только числа; формат
   и локализация — на HUD.
3. Не отправляй группу, если данных нет; отдельной команды очистки не требуется.
4. Держи «последнее известное» в своём состоянии и переотправляй в пределах §9.2 —
   приёмник не обязан помнить пропуски.
5. Не смешивай источники до отправки: notification/screen согласуются существующим
   `SourceSelector`, в протокол уходит уже согласованный снимок.
6. Ограничивай тексты 64 байтами; не шли адреса, POI и рекламу из уведомлений.
7. Новые данные добавляй новым id группы или новым значением enum в конце списка;
   не меняй раскладку существующих групп.

### 11.2 Приёмнику

1. Не блокируй BLE-стек отрисовкой: буфер + отдельная задача рендера.
2. Считай CRC; при ошибке держи прошлый кадр, но после 3 ошибок подряд покажи значок
   «данные повреждены».
3. Не мигай на повторном одинаковом снимке — сравнивай содержимое, а не факт прихода.
4. Неизвестные TLV/значения — молча пропускай; не сбрасывай из-за них экран.
5. Не экстраполируй дистанцию/время и не «дотягивай» стрелку: только watchdog §9.3.
6. Единицы — SI (м, с, м/с, км/ч в подписи); никаких «сотен метров» и прочих масштабов.
7. Храни только текущее состояние (`< 1 КБ`), история не нужна.
8. Логируй только `sequence` и ошибки CRC; персональных данных в канале нет.

### 11.3 Чего не повторять из C1

Нет версии схемы, аддитивная «сумма» вместо CRC, base64-обёртка `^…$`, фиксированный
порядок команд, единицы в сотнях метров, принудительный ASCII-транслит, 12 полос
с паддингом, отсутствие forward-compat, «второй манёвр» как копия первого.

## 13. Reference decoder (нормативные шаги)

```python
def on_write(pkt, now_ms):
    if pkt[0] == 0xFA:
        i, total = pkt[1], pkt[2]
        if total == 0 or i >= total: reset_frag(); return
        if i == 0: frag_entries, frag_total = [], total
        if total != frag_total or i != len(frag_entries): reset_frag(); return
        frag_entries.append(pkt[3:])
        if i + 1 < total: return
        msg = b"".join(frag_entries); reset_frag()
    else:
        msg = pkt
    if len(msg) < 13 or msg[0] != 1 or msg[1] not in (1, 2): return
    if u16le(msg[-2:]) != crc16_ccitt_false(msg[:-2]): return
    tlvs = parse_tlvs(msg, start=8, end=len(msg)-2)   # dict: последний дубль побеждает
    if msg[1] == 1: apply_state(tlvs, now_ms)         # G0 обязательна
    else:           apply_position(tlvs, now_ms)      # ровно одна 0x0A
```

`parse_tlvs` обязан проверять границы (`i + 2 + len <= end`) и точное `len` для известных
групп; группа с неверной длиной отбрасывается, остальные применяются.

## 14. Definition of done

- [ ] Все 7 сообщений §12.1–12.7 применяются byte-for-byte; CRC отклоняет испорченный байт.
- [ ] MTU 23: сообщение №2 собирается из 5 чанков; потеря среднего чанка → отброс, экран цел.
- [ ] Сообщение №3 (камера без манёвра) не гасит улицу/лимит/остаток и не показывает стрелку.
- [ ] `mode=idle` гасит все зоны одной посылкой.
- [ ] `lane_count=0`/отсутствие G2 гасит полосу; повторный снимок не мигает.
- [ ] Кириллица 64/65 байт: обрезка по code point, без битых глифов.
- [ ] 3 с тишины → `STALE`; 15 с → чисто; возврат потока восстанавливает экран.
- [ ] `version=2`, `type=9`, неизвестный TLV-id игнорируются без порчи кадра.
- [ ] G9 старше 5 с скрывается; `accuracy > 100` не показывается.
- [ ] Разрыв и повтор `sequence` не меняют отображение.
- [ ] Отключение BLE → очистка навигации ≤ 1 с.

## 15. Чего источник не даёт

Имя и координаты точки назначения; абсолютное время прибытия; второй и последующие манёвры;
круговое движение, номер/угол съезда; тип камеры (только «камера»); число полос > 8;
сигнал светофора; своя база камер/лимитов; полилиния маршрута; различение
«плавно»/«держитесь» источником (склеено, §2.2 D2); данные Яндекс Карт
(источник — только `ru.yandex.yandexnavi`).

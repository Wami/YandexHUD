# ESP32 HUD — спецификация канала, v1 (черновик)

Документ описывает данные и канал «Android → ESP32-HUD» **с нуля**. Формат WiiYii C1
(`src/YandexHudHeadUnit/HudProtocol.cs`) не используется и не наследуется: он не имеет
версии схемы, CRC, фрагментации и передаёт расстояния в сотнях метров.

Статус: **проект, не реализован**. На стороне Android транспорт — `IHudTransport` /
`IHudLocationTransport` (`src/YandexHudHeadUnit/HudTransport.cs`), кодировщик v1 ещё не написан.
Источник данных — `YandexNotificationBridge.BridgeState` (то, что реально читается из
Навигатора). Этот документ — контракт для прошивки HUD; всё, чего нет в §4–§5, передавать нельзя.

Ключевые слова MUST / MUST NOT / SHOULD / MAY — нормативные (RFC 2119).

---

## 1. Инварианты

1. Каждое сообщение — **полный снимок**, а не дифф и не команда. Приёмник не хранит историю.
2. Снимки самодостаточны: пропуск, дубликат или переупорядочивание не ломают состояние.
3. Всё, чего нет в данных, передаётся как «нет» и **обязано** гасить свой элемент на экране.
4. Отправитель не обязан дедуплицировать: одинаковый контент приходит повторно каждые ~750 мс.
5. Приёмник MUST игнорировать незнакомые `version`, `type`, резервные байты и значения
   enum, не выходя из строя и не рисуя «случайную» стрелку.
6. Все многобайтовые целые — **little-endian**. `f32`/`f64` — IEEE-754 LE. `NaN` = «нет значения».

## 2. Транспорт

| Параметр | Значение |
| --- | --- |
| Роль | ESP32 = GATT peripheral, Android = central |
| Service UUID | `6b1d0001-9c4e-4b7f-a1e2-3f5d6c7b8a90` |
| Characteristic `nav` | `6b1d0002-9c4e-4b7f-a1e2-3f5d6c7b8a90`, свойства `Write` + `Write Without Response` |
| Characteristic `status` | `6b1d0003-9c4e-4b7f-a1e2-3f5d6c7b8a90`, `Notify`, MAY (v1 не обязательна) |
| Advertising | имя `YHUD-ESP32` и/или Service UUID; по ним Android фильтрует скан |
| Pairing/bonding | не требуется |
| MTU | Android SHOULD запросить 185; прошивка MUST корректно работать при MTU 23 (payload 20 B) и 247 |
| Запись | отправитель предпочитает `Write Without Response`, при отсутствии — `Write` |
| Чтение/notify со стороны Android | не используются в v1 |

UUID — предлагаемые; при первом релизе зафиксировать и больше не менять (это идентификатор
протокола, а не настройка).

## 3. Контейнер сообщения

```
off  size field        value
0    1    version      1
1    1    type         1 = nav snapshot, 2 = location
2    4    sequence     u32 LE, +1 на каждый снимок, wrap по 2^32
6    2    reserved     0 (приёмник MUST игнорировать)
8    ..   payload      по типу (§4, §5)
N-2  2    crc          CRC-16/CCITT-FALSE от bytes[0 .. N-3], LE
```

CRC: poly `0x1021`, init `0xFFFF`, refin/refout = false, xorout `0x0000`.
Тест: `crc16("123456789") == 0x29B1`. Несовпадение CRC → отбросить сообщение целиком,
предыдущее состояние сохранить.

Минимальная длина: 8 (header) + payload + 2 (crc). Сообщение с `len < 10` отвергается.

## 4. Payload `type = 1` (nav snapshot)

Фиксированная часть 32 байта + два UTF-8 поля. Смещения — от начала payload.

```
off  size type   field                  значение / «нет данных»
0    1    u8     mode                   0 idle, 1 route, 2 free
1    1    u8     maneuver               enum §6; 0 = none
2    4    u32    maneuver_distance_m    0..2_000_000; при maneuver=0 всегда 0
6    4    u32    remaining_distance_m   0..50_000_000; 0 = маршрута нет
10   4    u32    remaining_time_s       0..3_000_000; 0 = маршрута нет
14   1    u8     speed_limit_kph        0 = нет; иначе 5..200
15   1    u8     road_event             enum §6; 0 = none
16   2    u16    road_event_distance_m  0..5000; 0 = расстояние не указано
18   2    u16    camera_distance_m      0..5000; 0 = нет предупреждения
20   1    u8     camera_state           0 none, 1 warning; distance>0 обязателен при 1
21   1    u8     lane_count             0..8; 0 = полос нет
22   8    u8[8]  lanes                  §6; байты за пределами lane_count MUST игнорироваться
30   1    u8     next_street_len        0..64 (байты UTF-8)
31   1    u8     current_street_len     0..64 (байты UTF-8)
32   var  utf8   next_street            ровно next_street_len байт
..   var  utf8   current_street         ровно current_street_len байт
```

Суммарный максимум payload = 32 + 128 = 160 B, сообщение ≤ 170 B → при MTU ≥ 185
уходит одной записью. `route_active` отдельным флагом не передаётся: это `mode != 0`.

## 5. Payload `type = 2` (location), 36 байт

```
off  size type  field            значение
0    8    f64   latitude         ±90
8    8    f64   longitude        ±180
16   4    f32   speed_mps        NaN = нет
20   4    f32   bearing_deg      0..360, NaN = нет
24   4    f32   accuracy_m       NaN = нет; > 100 → не использовать
28   8    i64   timestamp_ms     unix ms
```

Частота ≤ 1 Гц, только при включённой пользователем передаче координат. Сообщение
самостоятельное: приёмник MUST NOT ждать location, чтобы применить nav snapshot.

## 6. Enum-значения

`maneuver` (lane `direction` — отдельная нумерация):

| # | maneuver | смысл |
| --- | --- | --- |
| 0 | `none` | стрелки нет → очистить зону |
| 1 | `left` | поверните налево |
| 2 | `right` | поверните направо |
| 3 | `left_wide` | плавно/широко налево |
| 4 | `right_wide` | плавно/широко направо |
| 5 | `left_sharp` | резко налево |
| 6 | `right_sharp` | резко направо |
| 7 | `left_fork` | держитесь левее |
| 8 | `right_fork` | держитесь правее |
| 9 | `u_turn_left` | разворот налево |
| 10 | `u_turn_right` | разворот направо |
| 11 | `straight` | двигайтесь прямо |
| 12 | `finish` | прибытие |
| 13 | `rerouting` | маршрут перестраивается |
| 14..255 | — | не присылаются; трактовать как `none` |

`mode`: `0 idle`, `1 route`, `2 free` (обзор дороги без маршрута).

`road_event`: `0 none`, `1 accident`, `2 roadworks`, `3 closed`, `4 hazard`, `5 speed_bump`.

`lanes[i]` — один байт: `bits 0..3` = направление, `bit 7` = рекомендуемая полоса.

| # | lane direction |
| --- | --- |
| 0 | пусто/не используется |
| 1 | straight |
| 2 | left |
| 3 | right |
| 4 | slight_right |
| 5 | u_turn_left |

Позиции идут слева направо без разрывов. Рекомендуемая — минимум одна; если ни одна не
рекомендована, полосы не передаются (`lane_count = 0`). Других рисунков полос источник
не даёт.

## 7. Тексты

- UTF-8, длина ≤ 64 **байт** на поле, без управляющих символов и переводов строк.
- Источник может содержать кириллицу; транслитерация в ASCII — только если шрифт HUD её
  не поддерживает (решение §11.2). Признак формата не передаётся: кодировка фиксирована.
- Обрезка — по границе code point; приёмник MUST NOT рисовать «битый» глиф.
- Пустая строка (`len = 0`) = «очистить поле», а не «оставить предыдущее».
- `next_street` — улица после манёвра, `current_street` — улица текущего движения.

## 8. Фрагментация

Если сообщение не влезает в `MTU - 3`, оно режется на чанки; иначе (SHOULD) пишется целиком.

```
off  size type field
0    1    u8   frag_magic  0xFA
1    1    u8   frag_index  0-based
2    1    u8   frag_total  1..255
3    ..   raw  data        до (MTU-6) байт, у последнего чанка — остаток
```

- Первый байт GATT-записи `0x01` → целое сообщение (§3), `0xFA` → фрагмент.
- Чанки одного сообщения идут подряд, 50 мс между записями; данные других сообщений
  между ними не вставляются.
- Сборка: совпадение `frag_total` и последовательных `frag_index` от 0; иначе — сброс
  частичного буфера. Таймаут частичной сборки — 1 с.
- CRC проверяется только на собранном сообщении.

Пример: nav-снимок 70 B при MTU 23 → 5 чанков по 20/20/20/20/5 байт (§12.8).

## 9. Время и свежесть

| Что | Значение |
| --- | --- |
| Отправка nav | каждые ~750 мс (цикл 50..1500 мс), без дедупликации |
| Отправка location | ≤ 1 Гц |
| Свежесть манёвра/маршрута у источника | 5 с, далее отправитель сам присылает сброс |
| Свежесть полос | 5 с |
| Свежесть камеры | 10 с |
| Свежесть GPS | 5 с; `accuracy_m > 100` — отбросить |
| Watchdog приёмника | 3000 мс без валидного nav → состояние `STALE` (значок), 15000 мс → погасить всё |
| `sequence` | с разрывом = пропуск; применить как обычно, историю не восстанавливать |
| Повтор `sequence` | применить как обычно (идемпотентно), но не мигать экран, если payload идентичен |

Приёмник MUST NOT сам экстраполировать расстояние/время и не «держать» старую стрелку
дольше watchdog.

## 10. Отображение

Зоны независимы; отсутствие данных в поле гасит только свою зону.

1. **Стрелка+дистанция** — только при `mode=1` и `maneuver ≠ 0`. `rerouting` рисуется
   отдельной индикацией без стрелки и дистанции. `finish` — прибытие; следующий снимок
   будет полным сбросом.
2. **Полосы** — при `lane_count > 0`; `lane_count = 0` гасит полосу целиком (никакого
   «пустого серого»).
3. **Текстовая строка** — собрать из ненулевых частей в порядке
   `speed_limit_kph`, `road_event (+distance)`, затем `current_street` (в свободной езде
   без манёвра — `current_street`; при активном маршруте — `next_street`). Разделитель
   `" | "`. Пустой результат = погасить строку.
4. **ETA** — при `mode=1`: `remaining_time_s` (>0) и `remaining_distance_m` (>0).
5. **Камера** — значок при `camera_state=1` и `camera_distance_m > 0`, плюс дистанция.
6. **Лимит** — часть строки; отдельного круглого знака в данных нет.
7. **idle** (`mode=0`) — погасить всё, кроме статуса связи.
8. Дистанции: `< 1000` → `N м`, иначе `N,N км`. Время: `≥ 3600` → `H ч MM мин`, иначе `M мин`.
9. Зоны MUST NOT перекрываться; строка обрезается по границе code point, не по байту.

## 11. Решения, принятые в этой редакции (требуют подтверждения один раз)

1. Одна характеристика `nav` для nav и location, различие по `type` — меньше сущностей.
2. Тексты — UTF-8. Транслитерация только при отсутствии кириллицы в шрифте; тогда
   формат меняется вместе с `version`.
3. Два текстовых поля (`next_street`, `current_street`) вместо одного склеенного: позволяет
   экрану выбирать, что показать в `route`/`free`.
4. Круговое движение — без отдельного индикатора: источник не даёт угол съезда.
5. GPS — включён в v1 как `type=2`, но опционален по настройке пользователя.
6. Watchdog: 3 с → `STALE`, 15 с → полная очистка.
7. Статусная характеристика — MAY; прошивка и приложение обязаны работать без неё.
8. Частота nav — 750 мс.

## 13. Reference decoder (псевдокод, нормативные шаги)

```python
frag_entries, frag_total = [], 0

def reset_frag():
    global frag_entries, frag_total
    frag_entries, frag_total = [], 0

def on_write(pkt: bytes, now_ms: int):
    global frag_entries, frag_total
    if pkt[0] == 0xFA:                       # фрагмент
        i, total = pkt[1], pkt[2]
        if total == 0 or i >= total: reset_frag(); return
        if i == 0: frag_entries, frag_total = [], total
        if total != frag_total or i != len(frag_entries): reset_frag(); return
        frag_entries.append(pkt[3:])
        if i + 1 < total: return
        msg = b"".join(frag_entries); reset_frag()
    else:
        msg = pkt
    if len(msg) < 10 or msg[0] != 1 or msg[1] not in (1, 2): return
    if u16le(msg[-2:]) != crc16_ccitt_false(msg[:-2]): return
    seq = u32le(msg[2:6])
    if msg[1] == 1: apply_nav(parse_nav(msg[8:-2]), now_ms)
    else:           apply_location(parse_loc(msg[8:-2]), now_ms)
```

`parse_nav` обязан проверять `lane_count ≤ 8`, `next_street_len + current_street_len`
внутри payload, `speed_limit_kph` в {0} ∪ [5..200]; при нарушении — отбросить сообщение.

## 14. Definition of done (чек-лист приёмника)

- [ ] Все 7 сообщений §12.1–12.7 применяются byte-for-byte; CRC отклоняет испорченный байт.
- [ ] MTU 23: сообщение №2 собирается из 5 чанков; потеря среднего чанка → отброс, экран не рвётся.
- [ ] `mode=0` гасит все зоны одной посылкой.
- [ ] `maneuver=0` при `camera_state=1` оставляет камеру и строку.
- [ ] `lane_count=0` гасит полосу; повторный снимок не мигает.
- [ ] Кириллица 64/65 байт: обрезка по code point, без битых глифов.
- [ ] 3 с молчания → `STALE`; 15 с → чисто; возврат потока восстанавливает экран.
- [ ] `version=2` и `type=9` игнорируются без паники и без порчи текущего кадра.
- [ ] Разрыв и повтор `sequence` не меняют отображение.
- [ ] Отключение BLE → полная очистка навигации за ≤ 1 с.

## 15. Что источник НЕ даёт (не проектировать)

Имя точки назначения; второй и последующие манёвры; угол/номер съезда на круге;
абсолютное время прибытия; своя база камер; отдельный знак ограничения; число полос
больше 8; координаты или полилиния маршрута; события за пределами списка §6; данные
Яндекс Карт (источник — только `ru.yandex.yandexnavi`).
